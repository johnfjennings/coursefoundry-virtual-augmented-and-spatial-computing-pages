Week 6

Interaction Design in XR

Analysis, patterns and evaluation

Good design is invisible. Bad design is everywhere.

Today’s session

  • Interaction design frameworks for XR
  • Analysing real XR experiences
  • Interaction patterns and techniques
  • Evaluation methods
  • Assessment 2 briefing

What is interaction design in XR?

Interaction design is the practice of designing how users act within a system.

In XR this includes:

  • how users select objects
  • how users move through space
  • how users manipulate digital content
  • how the system provides feedback

Why XR is different

Traditional interfaces usually assume:

  • 2D screens
  • mouse, keyboard, or touch input
  • a fixed viewpoint

XR systems introduce:

  • 3D space
  • body-based interaction
  • dynamic viewpoint
  • spatial audio, haptics, and embodied feedback

The interaction loop

If any part of this loop is weak, the experience feels awkward, confusing, or uncomfortable.

Core interaction questions

When analysing an XR experience, ask:

  1. What is the main input method?
  2. How does the user select or manipulate things?
  3. What feedback does the system provide?
  4. How does the user move?
  5. What makes the interaction intuitive or frustrating?

Input methods in XR

Input type Examples Typical strengths
Controllers Quest 2, Vive Pro Precision, reliability
Hand tracking Quest 3, HoloLens 2 Natural interaction, low abstraction
Gaze Pico Neo Eye, HoloLens 2 Hands-free targeting
Voice HoloLens, mobile AR Command input
Body movement Room-scale VR Embodiment and presence

Selection techniques

Technique Description Typical use
Raycasting Pointing at a distance Menus, distant objects
Direct touch Touching/grabbing virtual objects Near-field interaction
Gaze and dwell Looking at a target for a set time Accessibility, hands-free systems
Pinch gesture Gesture-confirmed selection Hand tracking workflows

Locomotion techniques

Technique Comfort Presence Notes
Teleportation High Medium Reduces sickness but can break flow
Smooth locomotion Medium to low High More natural, but can induce discomfort
Room-scale movement High High Excellent when space allows
Dash movement Medium Medium to high Useful compromise

UI paradigms

Diegetic UI

UI that exists within the world.

Examples: - a wrist display - a control panel on a wall - buttons attached to equipment

Non-diegetic UI

UI that exists outside the world fiction.

Examples: - HUD overlays - floating menus

Spatial UI

UI arranged in 3D space and anchored to the user or environment.

Examples: - world-locked panels - anchored windows in mixed reality

Presence, usability and comfort

Good interaction design in XR should consider:

  • presence: does the interaction support the feeling of being there?
  • usability: can users understand what to do?
  • comfort: does the interaction reduce fatigue, confusion, and motion sickness?
  • accessibility: can different users complete tasks successfully?

Framework for analysis: PACT

Element Questions
People Who are the users? What abilities, expectations, or limitations matter?
Activities What are they trying to do?
Contexts Where and when is the interaction taking place?
Technologies What hardware, software, sensors, and constraints shape the experience?

PACT is a useful way to structure your case study.

Example 1: Beat Saber

Aspect Observation
Input Two 6DOF controllers
Interaction Direct embodied slashing
Feedback Strong visual, audio, and haptic feedback
Locomotion Stationary
Strengths Intuitive, immediate, highly embodied
Weaknesses Can be physically tiring, limited interaction range

Example 2: Pokémon GO

Aspect Observation
Input Touchscreen, mobile camera, GPS
Interaction Tap, swipe, movement through physical space
Feedback Visual and audio

Strengths Blends physical and digital context

Example 3: HoloLens 2 spatial interface

Aspect Observation
Input Hand tracking, gaze, voice
Interaction Air tap, grab, spatial manipulation

Weaknesses Narrower field of view than ideal, interaction learning curve

Evaluating XR experiences

Evaluation helps us understand:

  • what works well
  • where breakdowns occur
  • what should be improved
  • whether the design supports user goals

Heuristic evaluation for XR

Useful adapted heuristics include:

  • visibility of system status
  • natural mappings between action and effect
  • user control and freedom
  • consistency of interaction patterns
  • prevention of accidental actions
  • clear affordances
  • reduced memory load
  • comfort and accessibility

Quick user testing in XR

A small user test can still be valuable.

Recommended process:

  1. Give the user a short task
  2. Observe where they hesitate or fail
  3. Ask what confused them
  4. Note physical discomfort or awkward movement
  5. Identify improvements

Common interaction problems in XR

  • unclear affordances
  • inconsistent controls
  • poor feedback
  • overcomplicated gestures
  • uncomfortable locomotion
  • UI placed too close or too far away
  • excessive physical fatigue

Linking this to your assignment

For Assessment 2, you will do three things:

  1. Analyse an existing XR experience
  2. Prototype one key interaction from that experience
  3. Evaluate your prototype

Assessment 2: what to analyse

Your analysis should consider:

  • interaction design
  • input and output systems
  • feedback
  • presence and immersion
  • strengths and weaknesses
  • comfort and accessibility
  • relevant HCI and XR design principles

Assessment 2: what to prototype

Recreate one key interaction using Unity or Lens Studio.

Possible examples:

  • object grab and manipulation
  • ray-based menu selection
  • gaze interaction
  • gesture input
  • teleportation or navigation mechanic

Keep it focused. A simple, functional prototype is better than an over-ambitious broken one.

Assessment 2: what to evaluate

You should discuss:

  • what works well in your prototype
  • what does not work as well as the original
  • what design compromises you made
  • what you would improve next

Suggested structure for the case study report

  1. Introduction to the chosen experience
  2. Critical analysis of the interaction design
  3. Description of the prototype
  4. Evaluation and reflection
  5. Conclusion

What strong submissions usually do

  • analyse rather than describe
  • connect theory to examples
  • focus on one interaction and do it well
  • identify clear strengths and limitations
  • use appropriate XR terminology accurately

Common mistakes to avoid

  • choosing too many interactions
  • describing features without critique
  • building something unrelated to the analysis
  • ignoring comfort or usability
  • failing to reflect on limitations

Week 6 lab activity

In the lab, you should:

  • choose your XR experience
  • identify one key interaction
  • begin your analysis notes
  • set up your Unity or Lens Studio prototype scene

Suggested discussion prompt

Choose an XR application and answer:

  • what is the core interaction?
  • why does it work?
  • what assumptions does it make about the user?
  • how could it fail for a novice user?

Key takeaway

A strong XR experience is not just technically impressive.

It combines:

  • appropriate input
  • clear feedback
  • comfort
  • usability
  • meaningful spatial design
